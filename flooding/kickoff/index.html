Why this matters

Flood maps decide where help goes first.

High River, homes abandoned after 2013 · Mpeel, CC BY-SA 4.0

During a flood, rescue teams need a map of where the water is, within hours, often under thick cloud.

Radar satellites (Sentinel-1) see through cloud, day and night, and their data is free.

One honest limit: a satellite passes the same place only every few days. Rain-only street flooding can drain in hours, so we focus on floods that last: rivers and coasts spilling into towns.

The answer key

■ water, drawn by hand

Smooth water bounces the radar away, so flooded fields turn black. Buildings bounce it straight back, so towns stay bright even when the streets are wet. That is the core difficulty.

The extra clue for towns

“Does this place look the same as last time?”

Coherence before

bright = unchanged between two passes

Coherence during

same tile, flood pass

Coherence measures how similar two radar passes are, from 0 to 1. The bright blobs are villages: buildings stay the same between passes.

Water in the streets should make a town's coherence drop, even if its brightness barely changes.

Here the whole tile got darker: fields changed too. Telling flooded towns apart from everything else that changed is the hard part, and why we need a model trained on labels.

Live UrbanSARFloods tile 20210727_Weihui_ID_23_63. Each tile has 8 layers: coherence (pre, during) and intensity (before, after), each in VH and VV.

Our data

Two public datasets, both used in published papers.

UrbanSARFloods

main dataset · CVPRW 2024 · CC BY 4.0

8,879 tiles of 512×512 pixels
18 flood events on 5 continents
8 layers per tile: coherence + intensity
3 classes: no flood · flooded open · flooded urban
Separate test scenes: Weihui, Nova Kakhovka, Jubba

Training archive ≈ 38 GB on Hugging Face

Sen1Floods11

comparison · CVPRW 2020 · cited ~480 times

4,831 tiles of 512×512 pixels
11 flood events on 6 continents
Radar (2 layers) + optical (13 bands)
2 classes: water · not water
446 tiles labeled by hand

≈ 14 GB on Google Cloud; mostly open areas

One event is Canadian: Sainte-Marthe-sur-le-Lac, Quebec, May 2019, when a dike broke and flooded a town.

What one training example looks like

An image with 8 layers, and an answer key.

import rasterio
x = rasterio.open("SAR/tile.tif").read()  # (8, 512, 512) float32
y = rasterio.open("GT/tile.tif").read(1)   # (512, 512) class ids

# layer order (from the authors, GitHub issue #7)
# 0,1  coherence before   VH, VV   (0 … 1)
# 2,3  coherence during   VH, VV
# 4,5  intensity before   VH, VV   (dB, about −25 … 0)
# 6,7  intensity after    VH, VV

x_A = x[[4,5,6,7]]   # experiment A: intensity only
x_B = x              # experiment B: + coherence

Your model reads the 8 layers and colours every pixel with one of the 3 classes.

Exactly the same job as the segmentation exercise in the course, just with more input channels.

Check the class ids in the GT files on day one; the paper and README describe the folders (NF, FO, FU), not the pixel values.

Where we want to push

One question, three fair experiments.

A

Intensity only

Before + after brightness. What most flood models use.

B

+ Coherence

Add “did this place change?” Expected to help towns.

C

+ Terrain

Add “how high is this pixel above the nearest river?” Water flows downhill.

Rules: same network, same training steps, only the input changes. Test on flood events never seen in training. Report IoU for flooded urban separately, over several random seeds.

Roadmap

From “I can open a tile” to a result.

WEEKS 1–2

WEEKS 3–4

B and C
